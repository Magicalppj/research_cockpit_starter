# 0.3.0 CLI Cutover

## Conclusion

0.3.0 是 breaking CLI release：public parser、help 与 command manifest 只保留 role-based canonical surface，不提供 alias 或 compatibility window；0.2.x 及更早 project data 与 artifact 仍可直接读取和继续写入。

## Before Upgrade

1. 提交或备份 canonical `research_cockpit/` truth source。
2. 从 plugin root 安装 0.3.0。
3. 运行 `research-cockpit validate --root <data-root> --json`。
4. 将 automation、agent instructions 与 templates 更新为下表 route。
5. 对 interaction migration、repair、legacy artifact storage migration、artifact compaction 或 managed GC 先运行 `maintenance_action_v1` dry-run。

## Replacement Table

| Removed 0.2.x routes | 0.3.0 route | Migration rule |
| --- | --- | --- |
| `node-context`, `agent-session-context`, `option-workstream-context`, `run-context`, `artifact-records`, `list-runs` | `work open` or retained `context` | Assignment work uses `work open`; known node without assignment uses bounded `context`. |
| `claim-option`, `claim-workstream` | `work claim` | Claim with assignment id and return packet in the same call. |
| `create-run` | `work start` | Runtime generates run id and starts the experiment atomically. |
| `update-run`, `record-gate-result`, `ingest-gate-result`, `ingest-artifact`, `record-finding`, `update-finding`, `create-artifact`, `link-artifact`, `update-node-fields`, `update-workstream-fields`, `create-note` | `work record` or `work close` | Use `work record` only for evidence that must be durable before close; otherwise include it in closeout. |
| `complete-run`, `complete-experiment`, `close-current-experiment`, `complete-experiments`, `create-followup-experiment`, `report-option-workstream`, `finalize-workstream`, `set-cursor` | `work close` | Submit one atomic `work_close_v1` result/cursor/evidence transaction. |
| `bootstrap`, `suggest-next-actions`, `assignment-view` | `coord overview` | Use paginated snapshot, filters and revision polling. |
| `add-node`, `apply-graph-plan`, `create-workstream`, `close-branch`, `update-status`, `set-agent-focus`, `sync-focus-actions`, `start-agent-session` | `coord assign` | Select `graph_plan` or `session` action with stable operation id. |
| `set-focus`, `apply-suggestion`, `update-suggestion-state` | `ui` | These are coordinator UI-state controls, not agent workflow operations. Use the UI buttons; workers follow their assignment packet instead. |
| `check-decision-acceptance` | `context` | Read the target decision with `--id <decision_id> --json --compact`; `decision_acceptance` contains the computed checklist. |
| `promote-artifact-record` | `coord review` | Use `action: promote_artifact` without `--assignment`; provenance is preserved in the same coordinator transaction. |
| `promote-decision`, `update-decision-evidence`, `update-decision-checklist`, `accept-decision`, `set-baseline` | `coord decide` | Select an explicit decision action in `coord_decide_v1`. |
| `lint`, `active-resources`, `worktree-audit`, `branch-audit`, `artifact-retention-audit`, `maintenance-audit`, `worktree-closeout` | `maintenance audit` | Run one consolidated read-only audit. |
| `repair-interaction-log`, `cleanup-suggestion-lifecycle` | `maintenance repair` | Use route-specific action and dry-run first. |
| `migrate-interaction-log`, `import-worktree-findings`, `migrate-terminal-next-actions` | `maintenance migrate` | Use explicit action; source evidence is preserved. |
| legacy artifact storage | `maintenance migrate` with `action: artifact_storage` | Plan one record first; migration is resumable and preserves source evidence on cross-filesystem copy. |
| `compact-artifacts` | `maintenance compact` with `action: artifact` | Dry-run one target; execution demotes one eligible graph artifact without deleting payload. |
| managed payload cleanup | `maintenance compact` with `action: artifact_gc` | Revision-bound plan, verified quarantine, then delayed purge for one Cockpit-managed record. |
| grouped `artifact ...` and `run ...` aliases | corresponding role route above | Grouped compatibility aliases were removed with their top-level targets. |

Retained unique commands: `init`, `ui`, `validate`, `build`, `commands`, `smoke`, `search`, `context`。

## Data Compatibility Guarantees

- Unknown fields in legacy nodes, assignments, agents, runs, artifact record files/records and related nested mappings survive read-modify-write.
- Existing gate YAML/JSON and payload files are not rewritten by unrelated mutations.
- Existing legacy artifact payload bytes, manifest bytes, stable paths, links and provenance refs remain readable. New evidence defaults to reference-only; explicit managed copy requires an external artifact root and never silently allocates legacy `artifacts/` storage.
- Legacy YAML interaction history remains an immutable prefix after segmented migration; new events append to the active backend.
- Ordinary reads and mutations do not rewrite every file to a new schema version.

## Rollback

CLI rollback means reinstalling the previous package version; do not reverse truth files mechanically. Before rolling back after a 0.3.0 mutation, validate that the older runtime understands any newly added truth fields. Artifact payload and legacy fields are additive, but assignment lease/result fields may be unknown to older workflow code.

Storage-specific migration, managed GC eligibility, exact retry, and workstream granularity are documented in [0.3.1 storage boundaries](0.3.1-storage-boundaries-and-workstream-tracking.md).
