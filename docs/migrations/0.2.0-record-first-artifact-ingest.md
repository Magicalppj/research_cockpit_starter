# Artifact Ingest Migration In 0.2.0

## Status

Historical migration note. It explains the 0.2.0 transition, but its standalone ingest and promotion commands were removed by the 0.3.0 one-version CLI cutover. Do not use the command examples below as current workflow guidance; see `docs/migrations/0.3.0-cli-cutover.md` and `docs/artifact-retention-policy.md`.

## 0.2.0 Decision

Version 0.2.0 changed experiment artifact ingest from implicit graph-node creation to artifact-record creation. Ordinary output became a lightweight record, while graph promotion required an explicit reason.

The canonical payload path remained:

```text
artifacts/<experiment_id>/<run_id>/
```

Only the default metadata representation changed.

## 0.3.0 Replacement

Current workers use one of two assignment-scoped paths:

- Final evidence: include `evidence_inputs` in `work_close_v1` and execute `work close` once.
- Evidence that must be durable before close: execute `work record` with `work_record_v1`, then reference the returned record id during closeout.

Existing 0.2.x artifact records, promoted graph nodes, manifests, payload bytes, retention fields, and provenance references remain valid. Ordinary reads and mutations do not force a bulk migration.

Use current discovery only when an operation is unknown:

```sh
research-cockpit commands --role worker --name "work record" --json --compact
research-cockpit commands --role worker --name "work close" --json --compact
```

The full old-to-new route table and breaking boundary are maintained in `docs/migrations/0.3.0-cli-cutover.md`.
