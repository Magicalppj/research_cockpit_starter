# 0.3.1 Storage Boundaries And Workstream Tracking

## 结论

0.3.1 将新 evidence 的默认路径改为 reference-only，并把 Cockpit-owned payload、legacy payload、state truth 与 Git projection 明确分开；assignment 只表示需要独立 owner 或 durable handoff 的阶段 workstream。

## State、Git 与 payload 边界

- `--root` 与 `RESEARCH_COCKPIT_ROOT` 指向 state root。新项目可通过 `.research-cockpit.yaml` 中的稳定 `project_id` 让主 checkout 与 worktree 解析同一份 external state；locator 不保存 machine-local absolute path。
- `<state-root>/storage.yaml` 配置 external managed artifact root。`RESEARCH_COCKPIT_ARTIFACT_ROOT` 可覆盖该配置；managed root 必须与 state root 分离。
- `artifact_records/*.yaml` 是 payload 的 provenance truth；record 的 storage、integrity、inventory、retention、lifecycle 与 availability 参与状态判断。payload bytes 不参与 `root_truth_revision`。
- `<state-root>/artifacts/` 是 legacy payload location：继续可读、可显式迁移，但新 evidence 不会隐式写入这里。
- dashboard 与 milestone ledger 是 projection；Git 不承担 runtime state 或 bulk payload 的同步职责。

## Evidence admission

`work_close_v1.evidence_inputs` 和 `work_record_v1` 使用同一 evidence contract。

- 未指定 `mode` 时使用 `reference`：runtime 只写 source URI、bounded inventory、integrity declaration 与 selected links，不复制 payload bytes。
- `mode: managed` 是显式选择：它要求 configured external managed root，在一次 stream 中 copy/hash 并原子发布 metadata；不会回退到 legacy `artifacts/`。
- 大目录或不完整 inventory 必须显式声明 retention。reference evidence 可以带 launcher 提供的 content 或 manifest digest；没有该声明时 runtime 只记录 inventory-level integrity。
- caller 仍只在 closeout 中提交 final evidence；只有 close 前必须 durable 的 evidence 使用 `work record`。

## Legacy storage migration

对一个 legacy record，先运行 dry-run：

```yaml
schema_version: maintenance_action_v1
action: artifact_storage
execute: false
parameters:
  record_id: record_legacy
  operation_id: migrate-record-legacy-001
```

```sh
research-cockpit maintenance migrate --root <data-root> --file <migration.yaml> --json --compact
```

确认 receipt 后，将同一 stable `operation_id` 的 `execute` 改为 `true`。迁移会排除 active assignment/run，验证 source、target 与 manifest；same-filesystem path 使用 verified rename，cross-filesystem path 复制并保留 legacy source。copy、hash 或 publish 中断时，使用完全相同的请求重试，而不是手工移动目录或新建 record。

## Managed payload GC

物理回收只适用于 `storage.mode: managed` 且 `ownership: cockpit_managed` 的 payload，顺序固定为：

```text
dry-run plan -> verify -> quarantine -> delayed purge
```

Quarantine 的 dry-run input：

```yaml
schema_version: maintenance_action_v1
action: artifact_gc
execute: false
parameters:
  record_id: record_managed
  operation_id: gc-record-managed-quarantine-001
  phase: quarantine
  purge_after_seconds: 86400
```

执行时将 `execute` 设为 `true`，并填入 dry-run 返回的 `state_revision`：

```yaml
parameters:
  record_id: record_managed
  operation_id: gc-record-managed-quarantine-001
  phase: quarantine
  expected_revision: root-v1:<revision-from-dry-run>
  purge_after_seconds: 86400
```

Purge 使用新的 stable `operation_id` 和 `phase: purge`，并先取得新的 dry-run revision。GC 会拒绝 active、must-keep、external、legacy、weak-integrity、inventory incomplete、路径不安全或 delay 未到期的 record。Quarantine 是同一 artifact filesystem 内的 rename；每个 prepared/final transition 都写入 immutable manifest。删除失败或 publish 中断后，只能使用同一请求恢复，不要手工删除 `.quarantine/` 中的 payload。

Graph artifact demotion 仍使用 `maintenance compact` 的 `action: artifact`，且永远不删除 payload bytes；不要将它与 `action: artifact_gc` 混为同一个操作。

## Workstream granularity

一个 assignment 对应一个 independently owned stage workstream。相同 research contract 下的 code edit、retry、seed、parameter adjustment、preflight 与多个 local attempt 复用该 assignment；final closeout 汇总 selected final 与 meaningful negative evidence。

documentation-only micro edit、progress read、smoke、mechanical retry 与 format fix 不创建 assignment 或 graph node。只有独立 owner、durable handoff、independent review 或可能改变 research judgment 的阶段性交付才经过 coordinator assignment gate。

## Upgrade checklist

1. 保留现有 legacy data，不执行 bulk move。
2. 为新 managed payload 配置与 state root 分离的 external root；未配置时继续使用 reference evidence。
3. 更新 launcher/template，使默认 closeout 不期待 `artifacts/` 内的复制副本。
4. 对每个 legacy payload 先运行 `artifact_storage` dry-run，再按需执行可恢复迁移。
5. 只通过 `artifact_gc` 处理符合条件的 managed payload；先 quarantine，后 delayed purge。
