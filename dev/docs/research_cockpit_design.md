# Research Cockpit Design Document

## Goal

Create a repo-native, graph-based research cockpit that helps both the human researcher and AI agents understand:

- current research stage
- active problems
- candidate solutions
- experiments and evidence
- accepted / rejected decisions
- next actions

The system should run on a remote GPU server with normal Python dependencies.

## Core Principle

The project is represented as a graph-structured research state machine:

```text
Stage -> Problem -> Option -> Experiment -> Decision
                   -> Artifact
```

Each node is stored as YAML. Detailed reasoning is stored as Markdown notes. Dashboards and UI data are generated by Python scripts.

## Node Types

### Stage
A high-level phase of the research project.

Examples:
- Dataset Construction
- Task Formulation
- Text Encoder Redesign
- Edit Model Design
- Backbone Comparison
- Paper Preparation

### Problem
A concrete issue blocking progress.

Examples:
- Event-level text control is weak
- Remove under overlap remains hard
- Need better dataset quality filtering

### Option
A proposed solution branch under a problem.

Examples:
- FLAN-T5-XL event branch
- CLAP semantic anchor
- Remove-specific suppression head

### Experiment
An empirical verification node.

Examples:
- FLAN-T5-only ablation on v2_150
- FLAN-T5 + CLAP anchor ablation

### Decision
A recorded ADR-style research decision.

Examples:
- Adopt unified edit-program formulation
- Use FLAN-T5 + CLAP for event branch
- Do not make TTS add a neural editing task

### Artifact
Datasets, checkpoints, figures, manifests, papers.

## UI Prototype

The UI is implemented with Streamlit + PyVis.

### Page 1: Dashboard
Shows:
- current stage
- current problem
- current option
- current hypothesis
- open risks
- next actions
- active problems
- recent decisions

### Page 2: Research Graph
An interactive graph showing:
- stages
- problems
- options
- experiments
- decisions
- artifacts

Features:
- node type filter
- status filter
- highlighted current focus path
- click/select node for detail panel

### Page 3: Experiment Matrix
Table view with:
- experiment id
- status
- dataset
- backbone
- parent option
- result summary

### Page 4: Agent Context
Displays the JSON context pack that should be given to AI agents.

## Agent Workflow

Before performing any task, an agent should read:

1. `research_cockpit/dashboards/agent_context_pack.json`
2. nodes listed in `current_focus_path`
3. relevant notes or experiment configs if needed

Agents should not silently overwrite accepted decisions.

## Update Workflow

### Add a node

```bash
python scripts/add_node.py --id problem_new --type problem --title "New Problem" --parent stage_text_encoder
```

### Build dashboard

```bash
python scripts/build_dashboard.py
```

### Launch UI

```bash
streamlit run ui/app.py --server.address 0.0.0.0 --server.port 8501
```
